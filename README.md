# PLASTIC SHOW — сайт

Многостраничный сайт танцевального проекта PLASTIC SHOW.
Next.js 15 (App Router) · TypeScript · Tailwind CSS 4 · GSAP · Lenis · WebGL.

Собирается в статический экспорт (`output: 'export'`) — разворачивается на
GitHub Pages, любом CDN или обычном хостинге, без Node-рантайма.

---

## Запуск

```bash
npm install
npm run media     # один раз: генерирует AVIF/WebP из assets/photos
npm run dev       # http://localhost:3000
```

Сборка:

```bash
npm run build     # результат — out/
```

## Как менять контент

Весь текст, цены, постановки и артисты вынесены в `src/content/`.
Править код компонентов для этого не нужно.

| Что изменить | Файл |
|---|---|
| Контакты, навигация, команда, регалии, география | `site.ts` |
| Постановки (и страницы `/shows/[slug]`) | `shows.ts` |
| Услуги | `services.ts` |
| Прайс-листы по городам | `pricing.ts` |
| Костюмы и процесс ателье | `costumes.ts` |
| Видео | `videos.ts` + файлы в `public/video/` |
| Размеры и LQIP изображений | `media.generated.ts` (генерируется) |

### Добавить постановку

1. Положить фотографию в `assets/photos/`, выполнить `npm run media`.
2. Добавить объект в массив `SHOWS` в `src/content/shows.ts`.

Страница `/shows/<slug>`, карточка в каталоге, ссылки в меню, `sitemap.xml`
и JSON-LD появятся автоматически.

### Добавить город в прайс

Москва и Екатеринбург работают по разным прайс-листам — это не скидка на один
и тот же лист, а разные структуры (в Екатеринбурге нет раздела гос. проектов,
иначе сгруппированы выходы гоу-гоу, постановка считается надбавкой). Поэтому
каждый город — отдельный набор групп и отдельный маршрут.

1. Добавить объект в массив `CITIES` в `src/content/pricing.ts`.
2. Создать маршрут `src/app/pricing/<slug>/page.tsx` по образцу
   `pricing/ekaterinburg/page.tsx` — он рендерит общий `<PriceList>`.

Переключатель городов, подвал, `sitemap.xml` и страница «О проекте`
подхватят город автоматически.

### Добавить видео

1. Положить файл в `public/video/`.
2. Добавить запись в `VIDEOS` в `src/content/videos.ts`.

Страница `/video` сама переключится с состояния «готовится» на сетку с плеером.

### Подключить CMS

Структуры в `src/content/` — обычные типизированные массивы. Чтобы перейти на
CMS, достаточно заменить их источник на загрузчик (Sanity, Contentful, Strapi,
локальный JSON), сохранив те же типы: `Show`, `Service`, `PriceGroup`,
`Costume`, `Video`, `TeamMember`. Компоненты менять не придётся.

## Изображения

`npm run media` берёт все `.jpeg/.jpg/.png` из `assets/photos/` и создаёт в
`public/media/` наборы AVIF + WebP шириной 480/768/1200/1800 px (тиры шире
исходника пропускаются), а также инлайновые LQIP-заглушки. Манифест пишется в `src/content/media.generated.ts`.

Компонент `<Media>` отдаёт `<picture>` с `srcset`/`sizes`, ленивой загрузкой и
размытой заглушкой. Оптимизатор Next не используется — файлы уже готовы, что и
позволяет собирать сайт статически.

## Видео

Исходники из архива — 4K с телефона, 30–90 Мбит/с; это на один-два порядка
больше, чем нужно веб-странице. На сайт кладутся сжатые превью: ~12 секунд,
720p по длинной стороне, H.264, `-movflags +faststart`, около 1,7 МБ каждое.
Больша́я часть архива снята вертикально, поэтому реальные размеры кадра
хранятся вместе с роликом и плееры не загоняют 9:16 в 16:9.

```bash
ffmpeg -ss 1 -i ИСХОДНИК.mov -t 12 \
  -vf "scale='if(gt(iw,ih),1280,-2)':'if(gt(iw,ih),-2,1280)':flags=lanczos,fps=25" \
  -c:v libx264 -preset veryfast -crf 26 -maxrate 1600k -bufsize 3200k \
  -pix_fmt yuv420p -c:a aac -b:a 64k -ac 2 -movflags +faststart \
  public/video/<slug>.mp4

npm run video     # перечитывает public/video → src/content/video.generated.ts
```

Отдельного списка роликов нет: у постановки есть видео ровно тогда, когда в
`public/video/` лежит файл с её слагом. Фоновые ролики главной —
`hero-landscape.mp4` (16:9) и `hero-portrait.mp4` (9:16), они длиннее и
качественнее, звук из них вырезан.

Где видео появляется:

| Место | Поведение |
|---|---|
| Первый экран главной | фото остаётся LCP, ролик подключается после первой отрисовки и проявляется |
| Витрина на главной | горизонтальный рельс, играет ровно один ролик — ближайший к центру |
| Плитки каталога | превью по наведению, `src` появляется только при первом наведении |
| Страница постановки | плеер по клику, до нажатия — только постер |
| `/video` | сетка постеров с фильтром по категориям, `<video>` создаётся при открытии |

Ничего из этого не грузится при `prefers-reduced-motion`, при включённой
экономии трафика и на слабых устройствах — там остаются фотографии.

## 3D-модель накладки на наушники

`npm run model` собирает накладку (чехол) на амбушюру полноразмерных наушников
с выпуклой надписью **PLASTIC SHOW** и кладёт результат в `assets/3d/`:

| Файл | Что это |
|---|---|
| `plastic-show-earpad-cover.stl` | замкнутая сетка в миллиметрах, готова к печати и к литью силикона |
| `plastic-show-earpad-cover.png` | превью в трёх ракурсах, рендерится тем же скриптом |

Модель параметрическая и не тянет за собой ни одной зависимости: оболочка —
поверхность вращения по эллиптическому основанию, надпись задана штриховым
шрифтом прямо в скрипте, переводится в поле расстояний и выдавливается по
нормали к поверхности. Поэтому буквы ложатся по куполу, а не сидят на плоской
площадке, и любой текст можно поменять на лету.

```bash
npm run model                       # ~265 000 треугольников, 3 секунды
node scripts/generate-earpad-model.mjs --text="PLASTIC" --quality=high
node scripts/generate-earpad-model.mjs --no-preview
```

Размеры собраны в константе `CFG` в начале файла — габарит 100 × 86 мм под
чашку AirPods Max, купол 14 мм, юбка 9,5 мм, стенка 1,6 мм с прижимным
буртиком по кромке. Надпись: кегль 7,6 мм, штрих 1,6 мм, рельеф 0,85 мм.
Расчётный расход силикона — около 17 см³ (≈ 19 г) на одну накладку, на пару
нужны две одинаковые детали: модель симметрична, зеркалить её не требуется.

Перед записью STL сетка проверяется на замкнутость (каждое ребро ровно в двух
гранях) и на положительный объём — слайсер на вывернутых нормалях молча
напечатал бы не то. Фаска буквы намеренно шире шага сетки: так край не
попадает между вершинами и не превращается в лесенку. Чтобы получить более
крупную сетку под фрезеровку или под печать соплом 0,2 мм, есть
`--quality=high`.

## Анимации и производительность

- **Smooth scroll** — Lenis, синхронизирован с GSAP ScrollTrigger.
- **Reveal** — один общий движок (`components/motion/Reveal.tsx`), управляется
  атрибутами `data-reveal`, `data-parallax`, `data-count`.
- **Переходы между страницами** — «занавес» из вертикальных панелей поверх
  обычной навигации Next; ссылки перехватываются, но modifier-клики и внешние
  ссылки работают штатно.
- **WebGL** — собственный фрагментный шейдер в hero (сценический свет, дымка).
  Написан напрямую на WebGL2: это один полноэкранный quad, Three.js добавил бы
  ~150 КБ без пользы. Рендерится в половинном разрешении и останавливается,
  когда уходит из вида или вкладка неактивна.
- **Слабые устройства** — `lib/capabilities.ts` отключает шейдер, курсор,
  магнитные кнопки и горизонтальный пин по реальным возможностям устройства
  (`pointer: fine`, число ядер, память, `save-data`), а не по ширине экрана.
- **prefers-reduced-motion** — полностью отключает Lenis, reveal-анимации,
  переходы и бегущие строки; контент при этом остаётся видимым.
- **Критический путь** — GSAP, ScrollTrigger, Lenis и курсор грузятся лениво
  (`components/motion/MotionRuntime.tsx`) и не блокируют первую отрисовку.

## Доступность

- Семантические landmark'и, по одному `<h1>` на страницу, ссылка «к содержанию».
- Полноэкранное меню и лайтбокс: фокус-трап, `Esc`, возврат фокуса, блокировка
  скролла, `inert` для закрытой панели.
- Лайтбокс листается стрелками и свайпом.
- Контраст текста ≥ 4.5:1 (`--color-ash` — 5.85:1 на фоне `--color-void`),
  акцент для мелкого текста — `--color-ember` (4.75:1).
- Все интерактивные элементы имеют доступное имя; тач-цели ≥ 44 px.

## Деплой

### Vercel

Две настройки, обе обязательные.

**`vercel.json`** — говорит, где лежит результат сборки:

```json
{ "outputDirectory": "out" }
```

В настройках проекта на Vercel framework выставлен в «Other», поэтому Vercel
не знает, что Next.js с `output: 'export'` кладёт файлы в `out/`, и без этой
строки отдаёт 404 на всех адресах. Если в настройках проекта переключить
framework на Next.js, файл можно удалить.

**Скрипт `vercel-build`** в `package.json` — просто `next build`.

Генерация изображений в деплой намеренно **не входит**: 223 фотографии
обрабатываются около 25 минут, и держать это в каждом деплое нельзя. Результат
(`public/media`) коммитится в репозиторий, поэтому сборка занимает минуту.

**Из этого следует одно правило:** добавили фотографию в `assets/photos/` —
выполните `npm run media` и закоммитьте то, что появилось в `public/media/`.
Иначе изображение не попадёт на сайт. То же с видео: файл кладётся в
`public/video/` руками, затем `npm run video`, затем коммит.

### Обычный хостинг (основной домен)

Часть российских сетей не пропускает TLS к Vercel по собственному домену, хотя
адрес `*.vercel.app` с тех же серверов открывается. Поэтому основной домен
обслуживается с обычного хостинга, куда `.github/workflows/deploy-hosting.yml`
выкладывает тот же экспорт по FTPS при каждом пуше в `main`.

Нужны четыре секрета репозитория: `FTP_HOST`, `FTP_USER`, `FTP_PASSWORD`,
`FTP_DIR`. Без них задача пропускается. `deploy/htaccess` копируется в
`out/.htaccess`: страница 404, MIME-типы для AVIF и видео, кэш неизменяемых
файлов, принудительный HTTPS. Сертификат выпускается на стороне хостинга.

### GitHub Pages

`.github/workflows/deploy.yml` собирает сайт и публикует `out/` на GitHub Pages
при пуше в `main` (нужно включить Pages → Source: GitHub Actions).

### Любой другой хостинг

Залить содержимое `out/` — это обычные статические файлы.

## История

До этого проекта в репозитории лежал одностраничный сайт (`index.html` плюс
панель `admin.html`). Он удалён, но остаётся в истории git — вернуть можно так:

```bash
git show 5b004e2:index.html > index.html
```

В Vercel прежние продакшн-деплои тоже сохранены и помечены как кандидаты на
откат, так что вернуться к старой версии можно одной кнопкой в интерфейсе.
